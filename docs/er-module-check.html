总体 ER 图模块 · 检查证据

全部图形由 src/utils/svgExport.ts → erSvg() + src/utils/erRouting.ts → routeRelations() 真实执行产出，无手工绘制。

场景共 7 个（默认示例 / 刷新后 / SQL 导入 / 并排联系 / 自反联系 / 单实体 / 显式折线）；此处展示命中问题的 5 个。

检查结论摘要

  • P0刷新页面 / 导出再导入后，实体绝对坐标 x、y 丢失，精心排布的布局退化为自动网格（见下方"场景 A vs 场景 G"对比）。
  • P0同一对实体之间的多条联系完全重合：菱形与连线精确叠在一起，除最后一条外全部不可见。
  • P1自反联系（source === target）被静默丢弃，图上不留任何痕迹。
  • P1基数标注压住实体框：默认示例中"管理员表"的 1 被白底完全遮死，"留言板表"的 N 被压掉近一半。
  • P2菱形间距过近（x=1080 处两枚中心仅差 39.5px）、Visio 导出对 ER 图不成形。

一、正常基线：默认示例（场景 A）

12 个实体 + 8 个联系，整体正交寻线质量良好：连线零穿越实体、菱形零压框、分组虚线框正确包裹 Spring Boot 模块。问题只出现在标注落点上。

二、默认示例中的标注缺陷（场景 A，放大红框处）

三处问题均来自 erRouting.routeRelations() 的落点计算：
① 基数 1 落在实体矩形内部，而实体在最上层绘制（白底不透明）→ 该基数完全不可见；
② 目标端基数按 dist = min(30, len×0.45) 回退取值，末端段仅 50px 时只退 22.5px，而实体半高 22px → 净空 0.5px，字被压边；
③ 菱形落点冲突时按 t 序列逐个试位，可用区间不足时只能挤在相邻位置。

三、P0：刷新 / 导出导入后布局退化（场景 A vs 场景 G）

App.tsx 的 configsToJson()（第 104 行，用于 localStorage 持久化）与 ExportDataModal.tsx（第 74 行，用于「导出全部数据」JSON）在序列化白名单里只写了 row / col / group，漏掉了 x / y；而 erSvg() 判断绝对坐标用的正是 data.x / data.y。 于是"写盘一次，绝对坐标即永久丢失"。

四、P0：同一对实体之间的多条联系完全重合（场景 C）

订单 → 用户 之间建了「下单 / 支付 / 退款」3 条联系。三者源/目标同行，自动选出同一条直线候选，菱形落点也都被判为合法，最终 3 个菱形、3 条连线全部堆叠在 (315,112)。由于后画的白色菱形会盖住前一个的标签，实际只有最后一条「退款」可见，另两条信息彻底丢失。
根因：routeRelations() 兜底分支在 5 个候选 t 全部冲突时 pick 仍保持 0.5，直接与既有菱形原位叠放，且同一实体对之间缺少"平行偏移"策略。

五、P0：SQL 导入场景下的菱形重合（场景 B）

6 张表 / 6 个联系（无绝对坐标，走自动网格）。菱形 #1 与 #5 落在同一像素点 (621,112)，同样是一方被另一方遮盖；另有基数标注压住实体左边缘。

六、P1：自反联系被静默丢弃（场景 E）

「员工 — 管理 — 员工」这类自反联系（source === target）在 routeRelations() 第 173 行被 if (!S || !T || S.id === T.id) continue 直接跳过， erSvg() 又只渲染 routedById 中存在的联系，最终画布上什么都不会出现， 用户不会得到任何提示（无连线、无菱形、无基数）。这是上下级、分类树、BOM 等常见建模场景。

↑ 该场景配置了 1 个实体 + 1 条联系，但输出中菱形 = 0、连线 = 0。

七、P2：其余观察

  • Visio 导出对 ER 图不成形：erVisio() 直接复用通用 exportToVisio() —— 菱形被画成 120×60 矩形、基数与联系名丢失、正交折线被重算为直线、布局由 calculateLayout() 重排，导出结果与屏幕所见不一致。
  • 菱形间距过近：场景 A 中 x=1080 处两枚菱形中心距 39.5px，菱形高 32px，视觉净空仅 7.5px。
  • 绝对坐标无法在界面维护：ER 编辑器只提供实体名 / 分组 / 联系字段，没有 x、y、row、col 输入；叠加 P0 的序列化缺陷，用户一旦点过"应用"，布局就再也回不到手工排布。
  • 字体宽度假设：entWOf() 固定按 12px 估算宽度，若实体通过 JSON 指定 fontSize，框宽不会随之变化（ER 编辑器目前无字号入口，属潜在问题）。
