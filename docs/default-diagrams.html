四类图的默认示例 + 顺带修掉的 12 个 bug

时序图 / 类图 / 活动图 / 部署图 现在都有开箱可用的示例，和已有的用例图、功能结构图、ER 图同属一套 公寓报修管理系统。下面四张图由内置 SVG 导出渲染器真实产出（与导出 PNG 同一套代码）。

时序图 · 业主提交报修

5 个参与者（角色画小人、数据库画圆柱）、11 条消息：同步=实心箭头，异步=开放箭头，返回=虚线+开放箭头。

类图 · 报修系统领域模型

8 个类：抽象类「用户」斜体、接口「Notifiable」带 «interface» 构造型，11 条关系（继承 / 实现 / 关联 / 依赖）。 关系线已裁剪到类框边界、按方位走正交折线；布局按依赖深度分三层（基础类/接口 → 子类 → 业务类）， 继承箭头自然朝上，不再有斜穿整图的长线（关系线总长 6197→1326px）。

活动图 · 报修处理流程

10 个节点、12 条流：按流程方向分层（开始 → 提交 → 判断 → 派单/有偿 → 上门维修 → 判断 → 评价/重新派单 → 结束）， 分支带 [是]/[否] 守卫条件；「重新派单 → 上门维修」是回边，因此不参与分层。 判断菱形按文字宽度自适应（不再溢出），所有流走正交折线。

部署图 · 三层架构

5 个节点：终端(«device»)、部署包(«artifact»)、应用服务器(立方体)、数据库(圆柱)、文件存储(«component»)， 技术栈标注贴在各自节点下方，4 条通信路径带协议标签。

顺带修掉的 bug（检查这四类图时发现）

图类型问题原因与修法
时序图参与者类型形同虚设编辑器可切换 角色/系统/数据库，但绘制时一律画成矩形 → 角色改小人、数据库改圆柱
时序图异步/返回消息箭头不合 UML异步与同步画法相同、返回消息用实心箭头 → 异步=实线+开放箭头，返回=虚线+开放箭头
类图抽象类名显示成字面量先拼 名 再整体转义 → 图上出现 "User" → 标记不转义、只转义文字
类图成员一多就被裁掉类框固定 120px 高 + overflow=hidden → 按属性/方法行数自适应高度，行距也按行内最高者计算
类图interface / enum 类型丢失只看 stereotype 字段，节点类型被忽略 → 由节点类型兜底出 «interface»/«enumeration»
活动图流程顺序被打乱按 sqrt 网格铺开（活动图是自上而下读的）→ 改为沿流程方向分层、同层横向居中；回边保持原层避免环上死循环
活动图节点/箭头相互重叠同理；分层后同层节点横向排列，节点零重叠（已验证）
部署图通信路径标注全部丢失生产者把标签写在顶层 label，绘制端却读 data.label → 统一用兼容读取（两处都读）
部署图组件/制品/设备退化成服务器编辑器状态只支持 server/database，切页签时非 database 一律被改成 server → 状态放宽到 5 种类型并原样传回
部署图技术栈标签浮空标签 y 固定 +100，矮节点（60~90px）下方留出大片空白 → 按各类型实际高度贴到节点下方
导出(SVG/PNG)关系箭头埋进框内部类图/活动图/部署图都用"中心到中心"画线，箭头落在目标框内部被盖住 → 统一裁剪到框边界
导出(SVG/PNG)与屏幕显示不一致屏幕走 draw.io、导出走内置 SVG 渲染器，两套排版各写一份 → 活动图分层算法抽成共用实现（rankOfFlow）
类图关系线斜穿整张图、标签被框压住网格摆位 + 默认直线走线：业主→设施那条直接穿过报修单，派单/0..* 被框盖住 → 改为按依赖深度分层（继承/实现定层、关联只参与层内排序）+ 按方位出/入口的正交折线。关系线总长 6197→1326px、最长 629→224px、交叉 0
活动图判断文字溢出菱形菱形固定 90×62，"设施是否在保修期"装不下（菱形内接矩形只有一半宽）→ 宽度按 2×文字宽自适应
活动图多余的跨图斜线我在默认图里多加了一条「提交报修申请 → 上门维修」（语义也不对）→ 删掉

验证方式

离线把四份默认数据跑通「解析 → draw.io XML 生成 → SVG 导出 → 持久化回环」，共 48 项断言全通过，包括：
· XML 良构（标签配对、& 转义）、坐标无 NaN；
· 持久化回环前后生成结果逐字节一致（写盘丢字段的回归）；
· 类图：抽象斜体是真标记、接口构造型、框高 ≥ 内容高度、11 条关系端点都落在框边界上；
· 活动图：层号与 y 单调一致、节点零重叠；
· 部署图：通信路径标签与技术栈都在、三种构造型齐全。
